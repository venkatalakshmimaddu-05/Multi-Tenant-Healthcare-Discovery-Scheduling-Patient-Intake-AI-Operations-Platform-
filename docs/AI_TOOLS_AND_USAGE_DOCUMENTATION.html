2. Agentic Tool Calling (Capability Manager)

The AI Agent interacts with the healthcare platform through strictly typed capability tools. The agent does not directly manipulate the database; it executes validated capabilities via CapabilityManager:

Capability 1: check_availability

{
  "name": "check_availability",
  "description": "Discovers available real appointment slots for a specific specialty, doctor, hospital, or timeframe.",
  "parameters": {
    "type": "object",
    "properties": {
      "specialty": { "type": "string", "description": "e.g. Dermatology, Cardiology, ENT" },
      "doctorName": { "type": "string", "description": "Optional specific physician name" },
      "hospitalId": { "type": "string", "description": "Optional specific hospital ID" },
      "timeframe": { "type": "string", "description": "e.g. today, tomorrow, friday, next_available" }
    },
    "required": ["specialty"]
  }
}

3. Clinical Knowledge Representation & Safety Rules

To eliminate medical hallucination and ad-hoc if/else patches, all medical intelligence is codified in a modular domain knowledge base (src/lib/clinical/):

  • 50+ Controlled Concepts: Standardized terms, natural-language synonyms, anatomical locations, and colloquial phrasings (e.g. "belly in knots" → abdominal pain, "pins and needles" → numbness/tingling, "room spinning" → vertigo).
  • 4-Way Assertion Polarity:
    • PRESENT: Confirmed symptom reported by patient.
    • NEGATED: Explicitly denied symptom (e.g. "no fever", "haven't vomited"). Preserved in denied_symptoms to prevent re-questioning.
    • UNCERTAIN: Equivocal presentation (e.g. "maybe a fever", "might have slight chills").
    • UNKNOWN: Unstated attribute.
  • Deterministic Red-Flag Layer: Independent safety rules run prior to routine scheduling. Mandatory emergency 911 / ER escalation that cannot be overridden by conversational prompts.
